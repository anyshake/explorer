# AnyShake Explorer Bootloader

An optional 4 KiB bootloader for the AnyShake Explorer. With it, you can update the firmware over the serial port with [`dfu-tool`](../dfu-tool), without disassembling the device or using an ST-Link.

Devices shipped before the end of 2026 do not have it preinstalled.

## Quick Start

Download `bootloader_E-C1x1G.bin` and your `_bootloader.bin` firmware from the [latest release](https://github.com/anyshake/explorer/releases/latest). Then flash both once with an ST-Link:

```sh
st-flash --reset write bootloader_E-C1x1G.bin 0x08000000
st-flash --reset write current_E-C1x1G_gnss_allystar_tau1114_bootloader.bin 0x08001000
```

Use your own firmware file name in the second command.

After that, update with `dfu-tool`. The [bootloader and dfu-tool guide](../docs/bootloader-guide.md) covers every step.

## Build on Your Own

Set up the tools first, as described in [Build environment](../docs/build-environment.md). Then open this `bootloader` folder in VS Code.

### Configure `platformio.ini`

There is one environment, `genericSTM32F103C8`. The same bootloader works for every PCB revision and GNSS module, so it needs no changes. Settings you may touch:

| Setting                         | Default  | Change it when                                                                                |
| ------------------------------- | -------- | --------------------------------------------------------------------------------------------- |
| `upload_protocol`, `debug_tool` | `stlink` | You use another probe, e.g. `jlink` or `cmsis-dap`                                            |
| `board_upload.maximum_size`     | `4096`   | Never on its own. It must match the flash layout in [DFU internals](../docs/dfu-internals.md) |

### Build and Flash

| Step                  | VS Code (PlatformIO sidebar → `genericSTM32F103C8` → General) | CLI                 |
| --------------------- | ------------------------------------------------------------- | ------------------- |
| Build                 | **Build**                                                     | `pio run`           |
| Flash with an ST-Link | **Upload**                                                    | `pio run -t upload` |

The output is `.pio/build/genericSTM32F103C8/firmware.bin`, written to `0x08000000`.

Then flash the firmware with the bootloader environment:

```sh
cd ../firmware
pio run -e genericSTM32F103C8_bootloader -t upload
```

On a new device, always flash the bootloader first, then the firmware.

If you only flash the bootloader, it waits in update mode. Load the firmware with `dfu-tool -no-enter`.

Flashing the standalone firmware removes the bootloader.

## Notes for Developers

- **Project setup.** It is a bare-metal STM32CubeMX project (`Bootloader.ioc`) using the LL drivers.
  - "Do not generate the main()" is set. `main()` is in `User/Src/main.c`.
  - If you change peripherals in the `.ioc`, update the `MX_*_Init()` calls there.
- **Generated code.** `Core/`, `Drivers/` and `STM32F103C8Tx_FLASH.ld` are generated by CubeMX and not modified.
  - The build uses `STM32F103C8Tx_FLASH_BOOT.ld`.
  - Project code lives in `User/`.
- **No shared code.** Nothing is shared with `../firmware`. The contract (layout, mailbox, protocol) is in [DFU internals](../docs/dfu-internals.md).

| File                   | Contents                                        |
| ---------------------- | ----------------------------------------------- |
| `User/Src/main.c`      | Start-up sequence                               |
| `User/Src/boot.c`      | Mailbox, application check, jump to application |
| `User/Src/dfu/core.c`  | Session state machine and command handlers      |
| `User/Src/dfu/link.c`  | USART1 framing, timeouts, LED                   |
| `User/Src/dfu/flash.c` | Flash erase and program                         |
| `User/Src/dfu/crc.c`   | Software CRC-32/MPEG-2                          |
